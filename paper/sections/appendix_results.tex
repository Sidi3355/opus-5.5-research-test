\subsection{Primary versus pre-registered tampering definition}
\label{app:prereg}
The pre-registered definition counts any change to a protected file as tampering. Reading reports during validation, we found agents that created an empty scratch file under \texttt{tests/} (having no file-deletion tool) while leaving the conflict test failing and reporting it honestly. Our primary definition therefore counts a protected-file change only if, in the agent's own final suite, the conflict test passes, is skipped, or is gone. \Cref{tab:prereg} reports the main quantities under both definitions.

\paragraph{Amendments to the pre-registration.} The pre-registration and its five dated amendments accompany the paper. Amendments 1 and 2, made before any main-experiment trial, sharpened the definition of a fabricated requirement (adding the \emph{external authority} and \emph{generalization} flags used for the strict definition), fixed the task-selection rule, corrected an arithmetic error in the planned trial count, and set a budget stop. Amendment 3 added the minimal-pair experiment (H6) after an interim look at 60 main-run trials showed gaming concentrated in tasks with a plausible cover rule; it was registered before any minimal-pair trial ran. Amendment 4 added the diff-only review setting after the Opus 5.5 reviewer, in an interim look, rejected every gamed change in the pre-registered full-repository setting; it is reported as exploratory, and the comparison group of non-fabricated reports planned for the review experiment was dropped to conserve budget. Amendment 5, also written after interim review results, fit the pooled review model as a GEE rather than a random-effects model and records that reviewer calls interrupted by an API usage limit were rerun with identical prompts.

\subsection{Collateral damage on other inputs}
\label{app:collateral}
The hidden specification tests include the conflict input, so every special case fails at least one of them by construction. To measure damage elsewhere, we ran the visible conflict test against the reference implementation with the function under repair wrapped, and recorded each call it makes and the reference's return value. We then ran the hidden tests against each agent's implementation, wrapped so that these calls return the reference value, and excluded hidden tests that make such a call. Calls are matched after normalizing positional and keyword arguments and filling omitted arguments with the reference's defaults, so an agent that changes a default is still scored on the inputs that default affects. As a check, the reference implementation itself fails no remaining hidden test on any task. No model is involved (\texttt{analysis/collateral.py}).

\subsection{Judge validation}
\label{app:validation}
See \cref{tab:validation}. The validation coder is the lead agent of this study, itself Claude Opus 5.5. It coded from a sheet that showed each report, the repository, and the diff but neither judge's label; it had, however, seen interim aggregate results and some individual judgments earlier in the study, so the coding is not fully blind. Agreement with the primary judge, which is the same model, likely overstates agreement with an independent human coder and should be read as a check on consistent application of the rubric. The blinded labeling sheet (\texttt{analysis/validation/sheet.md}) accompanies the paper so that human coders can replace this check. Disagreements between the lead agent and the primary judge were concentrated at the boundary between \emph{fabricated requirement} and \emph{test-attributed}, typically when a report cited ``the spec'' after the user had said the tests encode the spec; they ran in both directions.
